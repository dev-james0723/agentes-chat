## Connected behavior and deliberate compatibility change

Query-only search retains its original metadata scoring and has no decision-model call. Task mode now requires a typed purpose: accountable_delivery_owner, department_coordinator, implementer or independent_reviewer. It must also specify an exact current target ID/handle or native department ID. These express requested intent, never permission or proven competence. The schema and both team/personal descriptions request the fields upfront so agents can fill already-known task context themselves.

Legacy task-only input now returns structured insufficient_scope with a reason before candidate/readiness/Judge expansion. This is an intentional behavior change, not backward compatibility. It directs the calling agent to fill missing fields/use metadata lookup; it does not automatically send another approval question to James. There is no language/title regex pretending to infer a department. A fuzzy query combined with task cannot broaden into the full roster or silently select the first lexical hit.

Exact ID/unique handle uses the rules path after native audience/autonomy/current requester/readiness filters. An optional department constraint must match the same agent; failure never switches to a manager or another specialist. Existing inLine remains an authorization reach exception, not a fitness preference. Native group membership is structural department evidence only; a group's leadUserId is a person, not an agent coordinator mapping.

A department-scoped shortlist is filtered before readiness reads and capped at8 candidates; excess scope returns clarification rather than truncating to oldest agents. Group ID is added to the existing loadTeam SELECT, not a new normal-turn query. After asynchronous readiness, original requester/active membership and bounded fresh agent/autonomy/audience/group rows are rechecked. These are explicit lookup costs, not a per-turn profile/skill/outcome scan. No capacity, account slot or execution lease is reserved.

Real scope/readiness-eligible candidates may still receive one calibrated JEV advisory ranking for the typed purpose. Uncertain competence is not treated as a permission failure. Every outcome explicitly retains taskFit=unverified and independence=not_evaluated; declared role, group, availability and confidence do not establish successful task qualification or independent-review acceptance. The caller itself remains excluded by native teammate logic, but full implementation-author provenance is not invented. Downstream work still needs actual verification and final native admission.

The runtime has no authoritative generic per-candidate exact-tool availability/needs projection. Nonempty requiredTools therefore returns tool_availability_unverified before a model call; it does not infer access from broad Code/Browser labels or create a new boolean broker. This is a bounded current limitation, not claimed full capability coverage. Future reuse of a real authoritative contract requires separate ownership review.

## Decision integrity and deadline

The existing chooseDelegate path keeps candidate membership, none, foreign-ID, malformed/outage and calibrated-only/no-paid-fallback semantics. It now includes purpose, bounded scope and explicit unverified-fit fields; rules decisions are not labeled as JEV calls. Duplicate/reserved candidate IDs and oversized shortlists fail before the Judge. Policy receipts use delegate/2 and continue to say approval not evaluated, capacity not reserved and dispatch not requested.

The same existing6-second timeout is also a local settlement deadline around the single Judge promise, including post-transport accounting waits. A monotonic elapsed-time check rejects late answers even if timer scheduling is delayed. Deadline returns unavailable/decision_deadline with one consumed decision call. No retry, replacement call, budget reset or late result promotion occurs; the race observes late rejection and clears its timer. Provider/accounting IO may continue and record usage. This does not cancel charges, globally bound native IO or implement a durable aggregate task/routine budget.
