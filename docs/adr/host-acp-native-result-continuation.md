# Native tool results and continuation for owner-bound ACP turns

Status: Proposed; source integration only. Extends ADR 0143 and ADR 0179.

The owner-bound ACP path uses the existing Tool Gateway for its qualified text-tool allowlist. Each call still requires the current run token, agent context, grants and approvals. ACP's own native permission requests remain denied. Model selection requires the CLI's exact returned selection, including the paired model/thought-level readback for Argon High. A title, model response or setter acknowledgement is not that proof.

The structured client requires the server-advertised version-3 run-state contract. Existing complete-only clients retain their completeness request. The ACP text path can consume a known completed result with explicit truncation or omitted-media metadata, but labels partial text and never claims that omitted media was inspected. Missing or contradictory completeness metadata stops the phase. Native image/PDF validation, owner-pinned host MCP profiles, phone opt-out and protocol 67 are retained; the minimum supported machine protocol remains 1.

Known completed tool errors can inform a subsequent, distinct intent through the same gateway. An unknown delivery or missing native history is fenced instead of replayed. Current-run native receipts reconstruct bounded observations after a pause; refusal, expiry or cancellation is treated as nonexecution only from a matching unclaimed native approval decision. A resumed native turn starts a fresh ACP session with the engine's available conversation and authenticated history. Duplicate mutation intents are refused; a repeated verification command requires an intervening confirmed workspace change.

The engine records CLI selection evidence and unknown-effect fences without replacing its existing file-sharing, metadata, provider-error or project-authority checks. Result metadata remains separate from authorization. No grant, dependency, schema, migration, configuration or installed process changes are included. Offline mock tests and source bundles do not qualify a deployed app/runner pair or real host tools; paired protocol-67 acceptance remains a separate gate.

Native runtime failures carry a closed `ACPdiag/v1` stage, cause and current-attempt effect tuple through the existing error message. Only native typed throw sites select that tuple; vendor/model text and lookalike errors use the bounded unknown diagnostic. A current attempt that was not dispatched says nothing about earlier effects in the turn: native receipts remain authoritative, unknown/completed tool-stop fences retain their existing codes, and every failure remains nonretryable. The diagnostic adds no protocol field, model-selection fallback, tool grant or replay. Offline synthetic ACP fixtures cover malformed intents after a completed observation, transport and authorization failures, schema changes, untrusted error lookalikes and unknown-delivery/duplicate-effect controls.
