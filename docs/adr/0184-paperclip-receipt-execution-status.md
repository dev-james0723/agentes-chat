# 0184. Receipt-scoped execution observations

- Status: Proposed; source-only, no producer is switched by this change.
- Extends: ADR 0180 (scoped native hook ingress), ADR 0182 (immutable workspace selection).

The compatibility lookup returns durable admission receipts. Its `queued`, `coalesced` and `skipped` values do not describe a worker's present execution or qualify its result. A separate read operation reports the linked native state without dispatching or changing that admission contract.

`POST /api/hooks/{token}/paperclip/status` accepts only `{idempotencyKey}`. An optional `Idempotency-Key` header must match. It reuses the same current token, configured signing secret, POST permission, IP/routine limits, bounded JSON body, plain native hook, mapping ingress opt-in, creator permission and organization checks as invocation/lookup. A cookie or caller-supplied organization, receipt, run, task, trigger, workspace or path is never accepted as authority. Dispatch switches can be paused/off while reconciliation remains available. Explicit credential, ingress, owner or organization revocation still refuses the read. Generic native hooks and the existing lookup response keep their behavior.

The response is `{contract: "agents_chat_receipt_status_v1", backend: "agents_chat", execution: null | observation}`. A missing key has `execution: null`. An observation contains its receipt/mapping/source identifiers, immutable `acceptedConfigHash` (also `configHash`), separate `currentConfigHash`, `admissionConfigStatus`, admission disposition, linked issue/routine-run/canonical receipt identifiers, a bounded workspace identity, nullable native enum states, `observation`, `reason`, `scopeQualification` and `evidenceQualified: false`. The contract appears on an observation too, so a future client can extract it explicitly. No current producer transport is wired to this new envelope.

Unknown legacy admission hashes remain null; they are never inferred from the current mapping or written back. A later mapping configuration or native definition change holds the observation while preserving accepted history. Current workspace/owner/agent/model/account/machine pins are checked using the registered binding rules. `scopeQualification: "qualified"` means those registry pins still match; it does not prove physical execution, model quality or outcome evidence. Malformed scope/status values are withheld. Host paths, account material, event/task text, transcripts, artifacts and error bodies are not projected.

After the existing hook locks, one joined statement reads the receipt's current pointer, same-organization routine run, issue, worker and canonical queued receipt together. Native deferral deletes/replaces its firing and moves all affected receipt pointers atomically, so the statement sees a consistent before/after state. It never selects the most recent run of a routine. No additional firing/worker row locks are acquired after the native-routine lock; a worker may already hold its firing while it waits on that routine. PostgreSQL contention qualification remains a separate gate.

Coalesced admissions can name the same work. Their native event names the original queued receipt, so the observation validates that queued receipt's issue/pointer/fingerprint/admission hash/workspace against the queried coalesced receipt and reports `sharedExecution: true`. A skipped admission names active work for admission reconciliation but did not start its own execution: it reports `not_started` with no execution statuses. Missing, foreign or inconsistent execution links report `held`, with no completion-bearing states or unrelated identifiers.

Known routine ledger states are `queued`, `starting`, `started`, `reported`, `silent`, `failed`, `canceled`, `superseded`, `missed` and `skipped`; agent and issue states use their native database enums. A done issue, done agent run or reported routine is an execution observation only. Nothing here returns verified success, findings, product approval or a continuation. A future artifact/outcome contract requires its own receipt/run/version/author/hash evidence and authorization review. Unknown states stay unverified rather than being translated to a passing outcome.

No dependency, schema migration, provider call, new grant or service is added. Tests use the existing PGlite and HTTP harness with synthetic credentials. They compare receipt, issue, job, hook-call, routine-run and agent-run rows before/after status reads, exercise coalescing/deferral, and retain the native authentication/refusal cases. Actual PostgreSQL contention, deployed network behavior, real models, source-producer wiring and caller cutover are not established by these fixtures. Removing this read route is a code rollback; it needs no history deletion or migration reversal.
