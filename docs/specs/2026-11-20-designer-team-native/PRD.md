# Designer Team Native Upgrade — Product Requirements
Revision: DT-2026-11-20-r1
Status: approved implementation scope from James's current request.
Target: existing Designer Team in James Engineering OS / Agentes Chat.

## Outcome
James gives a product or creative brief once. The existing team selects relevant capabilities, keeps the correct brand and language, creates the required artifacts, reviews real output, and reports the actual delivery state.
Retain ten existing identities and their current model/access assignments.

## Verified baseline
The live app is a Colima container; host source does not hot reload.
Native skills already expose metadata progressively, and run_skill_script executes versioned packaged Python/Node/shell resources.
The ten designers share 127 enabled skills. The problem is overlapping routing and incomplete production contracts, not loading 127 full bodies on every turn.
Research blueprint: James-Engineering-OS-Design-Team-Blueprint-2026-11-20.md (prior conversation, retained artifact).
Existing design-review requests outbound telemetry/paid reports. Existing director precedence and some native references are incorrect.

## Scope
Implement a native skill extension, maintenance/deployment tooling, targeted legacy text corrections, and managed sections for the current ten designers.
Reuse existing craft skills. Include selected upstream methods in scoped guidance and provenance; do not install competing orchestrators.
Publishing validation does not itself publish anything or introduce a new approval workflow.
Do not rebuild the live app, alter models, revoke tools, change unrelated team instructions, or use other sessions' working trees.
Real brand facts, assets and preferences must come from existing project sources. Synthetic verification fixtures must say TEST.

## Flow
Brief -> structured task -> executable planner -> one owner and collaborators -> real production tools -> independent rendered review -> delivery validator -> actual status.
Small fixes get proportionate work. New directions may use concept exploration.
Unavailable tools are reported by capability stage; configuration is not proof of execution.

## Evidence
Public source decisions and immutable revisions are retained in the skill provenance.
Current implementation seams were inspected in the running container: executor/context progressive disclosure, skill-tools, sandbox-tools run_skill_script, native import/assignment routes.
No paid service or new external account is required.
