# Project design memory

## Scope decisions

Use the current task, existing project documents and native knowledge tools as the starting point. Keep decisions attached to their brand and project rather than creating an unscoped global taste file.

For each useful decision, retain the project identity, source, date or task reference, affected artifact/version, rationale and status such as proposed, accepted, rejected or superseded. Record unknowns as unknowns. Generated output alone is not evidence that James approved a preference.

## Resolve context

- Prefer the current explicit request when it intentionally changes an older decision.
- Load only the relevant brand's context. Keep shared operational methods separate from brand-specific colors, voice, components and references.
- Preserve the reason behind an accepted constraint so a future task can distinguish a requirement from an old implementation accident.
- Make low-risk assumptions explicit and continue. Ask when conflicting sources would materially change the result.
- Avoid copying private account identifiers, session material or credentials into repository guidance.
- Use actual available storage and native tools. A catalog method does not prove that a particular knowledge connector exists.

When the task closes, update the existing decision location with accepted changes and useful review findings. Do not promote rejected concepts or synthetic research into durable brand facts.
