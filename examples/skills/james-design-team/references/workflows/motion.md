# Motion and video

## Choose the deliverable and stack

Distinguish interface motion, a storyboard, an animated asset and a finished video. Record the requested duration, aspect ratio, playback context, audio/caption needs and editable source. Use the current project's stack and available rendering tools.

`motion-foundations` provides conventions for React/Next.js work using `motion/react`. Do not apply its API rules to SwiftUI, GSAP, Hyperframes or other implementations. Select the relevant implementation guidance and inspect existing project dependencies before adding another animation system.

## Produce

- Give motion a purpose: explain state, direct attention, show continuity or express the campaign's rhythm.
- For interface work, define entry, exit, interruption and reduced-motion behavior. Verify that animation does not block input or obscure important information.
- For narrative video, develop a shot sequence with timing, framing, copy, transitions and audio intent before the render.
- Create or obtain the actual visual and audio inputs required by the task. Keep usage rights and source attribution with the production record when relevant.
- Render the requested output and play it back. Check cuts, text legibility, captions, audio alignment, cropping and beginning/end behavior.
- Retain editable source and output settings. Prompts, JSON scenes, storyboards and unrendered timelines are intermediate artifacts when a finished video was requested.

## Review

The independent reviewer needs the actual playback artifact and target context. Stills can support composition feedback but cannot establish timing, audio or interaction quality. Record untested behavior and follow [review](review.md) and [delivery](delivery.md).
